【第 1 頁｜封面】主講：前端
--------------------------------------------------------------------------------

大家好，今天要報告的是 JSBridge 整合方案。

這個方案的核心目標：讓 App 端與 Web 端都站在同一份規格上開發

做法是去實做一個以可重複使用的模組化 SDK，方便我們在開發 webview 專案時可以提高串接 JSBridge 的效率。

以下有一些綠色的 tag ，這些關鍵字就是構成這次專案的幾項重點與目標

【第 3 頁｜什麼是 JSBridge】主講：前端（App 可短補）
--------------------------------------------------------------------------------

什麼是 JSBridge？
JSBridge 是 Web 與原生 App 之間的通訊橋樑。

有些案子會需要在 App 裡面嵌入網頁時（也就是所謂的 webview）
在實務上有可能會需要在兩者之間傳遞訊息，
那個傳遞訊息的動作就要透過 JSBridge 來完成

會有兩個方向：
  · Method：Web → App，比如說請求 App 開啟原生相機 或是跟 App 拿取使用者資料等等。
  · Event：App → Web，App「主動通知網頁」，例如點擊一個按鈕之後，需要 Web 開起某個彈窗之類的。


--------------------------------------------------------------------------------
【第 4 頁｜痛點與提案】主講：前端
--------------------------------------------------------------------------------

為什麼要做這件事？先來看一下以前的作法跟痛點。

以前每個專案各自做 Bridge，雖然我們是會寫文件，
但是這些文件常常散落在各專案，並沒有統一的管理方式。

並且那這會出現一個問題
我們在開發時會來文件這邊看規格 手抄這些欄位或是方法的名稱等等，
偶爾會出現比如說拼字的錯誤 或是 參數有缺漏等問題 導致測試的時候功能失效

以及如果未來多一個功能 就要回來文件這邊反覆核對名稱、欄位與回傳格式；

這些事情很繁瑣 所以我們的目標是希望
做出一個能夠共用在各專案的方法 並且統一管理
然後以規格來驅動：codegen 的方式產出三端所要用到的程式。
前端呼叫封裝好的介面；App 只要專心實作業務邏輯就好
並且減少手動寫code的錯誤


--------------------------------------------------------------------------------
【第 5 頁｜預期效益】主講：前端
--------------------------------------------------------------------------------

這樣做預期有三個效益：

一、少三方會議：Web／iOS／Android 以規格為準，不必每加功能就開會對欄位、對字串。
二、可重複使用：掃碼、導頁、語系等打成共用模組，新專案裝套件即可，不必重寫 Bridge。
三、減少不一致：三端同版本號發版，加上禁止手打 wire，降低「Web 有、App 沒有」與來回溝通。

可量化上，新 method 從「三方各自開發、反覆對規格」，
變成「改規格 + codegen + 各端實作業務」；
跨平台字串 bug、文件過期、sample 複製錯誤，以及對齊會議次數，都應該明顯下降。


--------------------------------------------------------------------------------
【第 6 頁｜三層架構】主講：前端（App 短補產品端）
--------------------------------------------------------------------------------

架構分三層，職責要分清楚。

第一層，共用 SDK：jsbridge-sdk。
放跨專案都會用的 method／event、通訊機制、錯誤碼，以及三端 codegen。
例如掃描、導頁、使用者資訊。（可點開看共用清單與訊息格式。）

第二層，專案套件：omniguider-bridge-contracts。
裡面會放專案專屬的方法，管理的方式很簡單，我們會在 packages 底下建立各專案的資料夾
資料夾名稱會自動對應我們到時候要import的路徑

那原本共用sdk跟bridge-contracts是要分開安裝的 但後來我們有將他合併
讓專案套件去依賴共用sdk 好處是只要安裝了專案套件也能使用共用的方法

依賴並 re-export SDK。例如海生館的 nmmba。
（可點開看目錄結構與使用方式。）

第三層，產品端：{projectId}-front、iOS、Android。
只安裝套件、呼叫裡面的方法並且專注在後面的業務邏輯就好


--------------------------------------------------------------------------------
【第 7 頁｜如何使用 · Web】主講：前端
--------------------------------------------------------------------------------

Web 端怎麼用：有專案套件時建議裝專案套件，例如
pnpm add @omniguider/nmmba-bridge-contract；
沒有專案差異再直接裝 @omniguider/jsbridge-sdk。

接著 import createBridge，本機開發可開 debug 與 mock，不必綁真機 App。
呼叫像 bridge.user.getInfo()、bridge.navigation.setHeaderTitle() 即可。

請前端同事記住四點：
  1. 用產生的 method／event 名稱，不要手抄字串
  2. 本機可用 mock
  3. 只裝專案套件就會一併帶入共用 SDK
  4. 不要在前端 repo 去發布專案套件


--------------------------------------------------------------------------------
【第 8 頁｜如何使用 · App】主講：App（iOS／Android 一起）
--------------------------------------------------------------------------------

App 端原則一樣：安裝 Host／專案套件，只實作業務邏輯。

iOS：走 Bitbucket + SPM。
建立 OmniguiderBridgeHost，install 到 WebView configuration，
再用 registerSend／相關 API 註冊業務。
版本用 tag：共用是 vX.Y.Z，專案是 {id}-vX.Y.Z。

Android：走 Reposilite Maven。
implementation 專案套件 AAR（會透過 api 帶到 kit），
registerSend 實作業務，需要時 emitEvent 推給 Web。
請不要用 git include，也不要複製 generated 檔。

兩邊共同重點：常數與骨架來自 codegen；我們只填「掃碼開什麼頁、關 WebView 做什麼」這類業務。

【第 9 頁｜如何運作】主講：共同
--------------------------------------------------------------------------------

（前端）Method：Web → App。
Web 發起，例如 await bridge.scanner.scanQr()；
需要回傳的是 invoke（有 requestId），單向的是 send（例如關 WebView）。
（可點開看 Web／iOS／Android 對照。）

（App）Event：App → Web。
App 主動推播，例如收藏更新；Web 用 onEvent 訂閱。
iOS 用 BridgeReply.event，Android 用 host.emitEvent。
（可點開看三端範例。）

通訊通道提醒一下：
iOS 是 omniguiderBridge，Android 是 OmniguiderBridge，
App 回 Web 走 window.onOmniguiderBridgeMessage。

【第 10 頁｜實際範例 · QR Code 掃描】主講：共同
--------------------------------------------------------------------------------

用掃碼走一遍完整、可追蹤的流程。左側點步驟，右側會切換內容。

（前端 · 步驟 1）
Web 前端發起標準 Bridge request：
按鈕觸發 await bridge.scanner.scanQr({ hint: "…" })；
SDK 會送出帶 requestId 的 wire 訊息，例如 method: scanner.scanQr。

（App · 步驟 2）
iOS／Android Host 收到對應 Handler，依 BridgeMethod.scannerScanQr 找到註冊的處理函式。

（App · 步驟 3）
在 Handler 裡開啟原生相機／掃描 UI，這段是純原生業務。

（App · 步驟 4）
掃描完成後，用「同一組 requestId」依約定格式回傳：
成功帶 data（content、format），取消或失敗帶 error（例如 USER_CANCELLED）。

（前端 · 步驟 5）
SDK 把 response 對回原本的 Promise；前端用結果更新畫面，或依錯誤碼提示使用者。

一句話：Web 發起與收結果，App 執行與回傳；中間靠同一份規格與 requestId 對齊。

【第 11 頁｜開發流程】主講：共同
--------------------------------------------------------------------------------

日常開發四步：改 JSON → codegen → release → 產品端 bump。

（前端）
1. 改規格：共用改 bridge.catalog.json，專案改 bridge.project.json。
   （可點「改 JSON」看 nmmba 範例。）
2. codegen：利用改好的JSON檔產出三端 method／event 名稱與 Host 骨架。
   （可點「codegen」看 Web／iOS／Android 產出。）
3. release：Web 發到 Verdaccio（npm）。
4. 產品端 bump：前端專案更新套件版號。

（App）
發版後 iOS 用 Bitbucket Exact tag + SPM 鎖定；
Android 用 Reposilite Maven 鎖定版號。
SDK 發版後必須 sync-contracts，專案套件跟著鎖定 SDK 版號，
再通知各產品手動更新——發版不會自動進產品專案。

發布管道對照：
  Web → Verdaccio　｜　iOS → Bitbucket tag + SPM　｜　Android → Reposilite Maven

【第 12 頁｜AI 在本專案】主講：前端
--------------------------------------------------------------------------------

這次落地，AI 實際幫了三件事：

一、盤點：收斂散落規格 分析舊專案 JSBridge 的串接方式，以及散落在各地的文件，
   我們把這些東西全部餵給ai，請他整理共用方法 與 專案專屬的功能。
二、規格：產出統一管理的JSON，便後續的維護
   並且定義好 共用SDK、專案套件、產品端三層職責。
三、產出：最後 實作出 gen code 流程 依照JSON去產出三方需要的程式碼，
   並且建立發版機制與流程。


--------------------------------------------------------------------------------
【第 13 頁｜總結】主講：前端（App 可收尾一句）
--------------------------------------------------------------------------------

總結兩塊。

核心做法：
  · 規格 JSON 為驅動
  · 共用進 SDK、專案差異進專案套件
  · 流程是改規格 → codegen → 發版 → 產品端更新版號
  · Web 呼叫／訂閱，App 註冊業務，不手打 wire

帶來改變：
  · 少三方會議、少對欄位與字串
  · 掃碼、導頁等能力可跨專案重用
  · 三端同版本號發版，降低不一致
  · AI 協助盤點、codegen 與發版流程

相關連結可會後自行查看：共用模組 JSBridge、專案 JSBridge、Verdaccio、Maven。

（App 收尾，約 15 秒）
原生端接下來就是依專案套件註冊 Handler、接業務；有新 method 也是改規格再 codegen，
不要各端手抄字串。以上是我們的整合方案，謝謝，歡迎提問。

四、Q&A 可能問題（備用）
================================================================================

Q：mock 寫在哪？
A：（前端）寫在各專案 createBridge({ mock })，不是寫死在 SDK。

Q：send 跟 invoke 差在哪？
A：有 requestId、Web 要 await 結果 → invoke；單向通知、不必回傳 → send。

Q：產品端能不能改 generated？
A：不行。只改 JSON，再 codegen。

Q：新專案怎麼擴充？
A：複製 packages/{projectId} 模式，專案 API 用 {projectId}.* 前綴，不要寫進共用 catalog。
