內部分享 · omniguider-bridge-contracts

網頁和 App 之間的「指令清單」，
前端自己就能新增、發佈

過去新增一個網頁呼叫 App 的指令，要找專人、等專人的電腦、手動上傳三個地方。這次把整段流程做成一個指令加自動化部署，前端改完檔案下一個指令就完成。

第 1 章 · 故事的開始

JSBridge 原本分成兩層，只有新專案裝得到

網頁和 App 之間傳話用的名稱，分成「大家共用的」和「某個專案自己才有的」兩層，放在兩個不同的儲存庫。

共用 · jsbridge-sdk

JSBridge SDK

每個專案都會用到的能力：掃描、導航、使用者資訊，以及傳話用的底層程式。

scanner.*navigation.*user.*
＋
專案專屬 · omniguider-bridge-contracts

專案 JSBridge

只有這個專案才需要的指令，例如海生館的「開啟 AI 辨識」。每個專案一個套件，裡面已經包含共用 SDK。

原本唯一的安裝入口：建立前端專案時順便裝

用 create-front 開新專案時選「安裝專案 JSBridge」，就會自動裝好套件、產生初始化檔。

缺的那一塊：沒辦法「單獨」安裝專案 JSBridge。
  • 已經存在的前端專案：當初不是用 create-front 建的，或建立時選了「不需要」。
  • 專案還沒有規格：要先有人到規格儲存庫幫它建好。
  • 規格要加新指令：只能找儲存庫負責人改、發版。

這次的工作就是補上這一塊，再一路做到自動部署。

程式和工具畫面上寫作「契約」

介面規格

網頁和 App 事先講好的「指令清單」：有哪些 method、哪些 event、名稱是什麼。每個專案一份，就是一個 JSON 檔。

以前唯一能發佈的人

儲存庫負責人

管理 omniguider-bridge-contracts 這個儲存庫的人（目前是 Ryan）。以前只有他熟悉流程，電腦上也只有他裝好發佈環境。

放在公司內網

套件伺服器

規格做成套件後要放的地方：網頁用 Verdaccio、Android 用 Reposilite、iOS 直接從 Bitbucket 的版本標籤（tag）下載。

一份規格，自動產生三端程式碼

規格只寫一次。工具會產生 TypeScript、Swift、Kotlin 三份常數，三端都引用常數，不用自己打字串，也就不會打錯。

bridge.project.json規格本體
{
  "projectId": "nmmba",
  "methods": [{
    "id": "uiOpenIdentify",
    "wire": "nmmba.ui.openIdentify",
    "kind": "send",
    "summary": "請 App 開啟原生 AI 辨識頁"
  }],
  "events": [{
    "id": "uiOpenGameGuideDialog",
    "wire": "nmmba.ui.openGameGuideDialog"
  }]
}

  "nmmba.ui.openIdentify"

  "nmmba.ui.openIdentify"

第 2 章 · 以前怎麼做

以前前端想加一個指令，要經過這些步驟

以「網頁要多一個按鈕，請 App 打開地圖」為例：

  1. 前端

    傳訊息給負責人

    說明要加什麼名稱、做什麼用。

    前端可以幫 nmmba 加一個 nmmba.ui.openMap 嗎？要請 App 開地圖頁 🙏
    等負責人有空
  2. 負責人

    在規格儲存庫裡手動修改 JSON

    打開 contracts 儲存庫加一段，並自己判斷這次算哪一種修改。

    omniguider-bridge-contracts / packages/nmmba/bridge.project.json
        { "id": "uiOpenMap", "wire": "nmmba.ui.openMap", "kind": "send" },    // 這算新增還是不相容修改？版本號要跳 minor 還是 major？→ 靠人判斷
  3. 負責人

    產生三端程式碼、檢查、提交

    每一步都是分開手動下的指令。

    pnpm run codegen:nmmba pnpm run check git commit -am "feat(nmmba): add uiOpenMap"
  4. 負責人

    在自己電腦上發版、建置 Android 套件

    發版指令會在本機建置 Android 套件，需要 JDK 17 和 Android SDK。換一台沒裝的電腦，就會停在這裡：

    pnpm run release -- nmmba --minor ERROR: JAVA_HOME is not set and no 'java' command could be found in your PATH.
    只有負責人的電腦可以
  5. 負責人

    從本機依序上傳三個地方

    一個接一個傳，中間任何一個失敗，要自己判斷哪些已經傳上去、哪些要補。

    iOS推送 tag nmmba-v0.2.0✓
    網頁上傳 Verdaccio✓
    Android上傳 Reposilite✗ 網路中斷

    舉例：如果傳到第三個失敗，前兩個已經發出去了，只能手動補傳最後一個。

  6. 前端

    收到通知後手動安裝新版

    自己設定套件來源、改版本號、重新安裝。

    .npmrc
    @omniguider:registry=http://10.61.102.143:4873/
    package.json
    "@omniguider/nmmba-bridge-contract": "0.2.0"
    再等一次

為什麼要找人？

當時只有給負責人用的指令稿，沒有給前端用的工具；流程也只有負責人清楚。

為什麼要手動？

改 JSON、產生程式碼、檢查、提交、發版是分開的指令，沒有串起來。新增一個專案甚至要手動複製整個資料夾，很容易漏改設定。

為什麼綁電腦？

Android 套件必須建置，建置需要數 GB 的開發環境，只有負責人的電腦裝好了。

第 3 章 · 做了哪些事

分四步，把「找人」和「手動」拿掉

做一個安裝工具

前端下一個指令 pnpm create @omniguider/bridge，選專案、選版本就裝好。新增專案也改用指令產生，不再手動複製。

前端自己改、自己發佈

規格檔放進前端專案的 bridge/ 資料夾。改完後工具自動比對差異、決定版本號、完成發佈。

交給 CI 自動部署

建置和上傳移到 Bitbucket Pipelines。前端電腦只要推一個版本標籤，不用再裝 Android 開發環境。用測試專案從頭到尾驗證過一次。

同仁實際使用

同仁實際用工具建立新專案並發佈，過程不用負責人介入。之後依回饋補上 npm／yarn 專案的支援。

示意畫面：文字取自工具實際輸出，uiOpenMap 是舉例用的指令，部分中間過程有省略。

  1. 自動發現有修改：工具拿你的檔案和目前安裝的版本比對，列出新增了什麼。
  2. 自動決定版本號：這次只有新增，所以從 0.1.2 升到 0.2.0。
  3. 先檢查再動手：確認網路、權限都沒問題才開始，避免做到一半失敗。
  4. 交給 CI：本機只推一個版本標籤，建置和上傳由 Bitbucket 完成。
  5. 自動裝回前端：發佈完成後，前端專案直接升到新版，最後提醒你通知 App。

按下確認之後，背後發生了什麼

前端電腦

檢查、產生程式碼

在暫存資料夾下載規格儲存庫，寫入你的修改並產生三端程式碼，完成後刪除。

前端電腦 → Bitbucket

推送版本標籤

推送 nmmba-v0.2.0。iOS 從這一刻起就能用這個版本。

Bitbucket Pipelines

自動建置

偵測到新標籤就開始執行：確認版本號一致，檢查並建置 Android 套件。

Bitbucket Pipelines

上傳兩個伺服器

網頁Verdaccio
AndroidReposilite
iOSBitbucket tag
建置失敗就什麼都不上傳；某一端上傳失敗可以重跑，已上傳成功的那一端會自動跳過。

版本號怎麼決定

0.1.2 → 0.1.3patch

只改了說明文字。

App 不用改程式
0.1.2 → 0.2.0minor

新增了 method 或 event，原有的都沒動。

App 升版後實作新的指令
0.1.2 → 1.0.0major

刪除或改名了既有的指令，舊版 App 會對不上。

工具會要求你輸入專案名稱確認，請先和 App 端講好

第 6 章 · 最後達成什麼

誰需要新指令，誰就能自己完成

目的不是多一個工具，而是讓介面規格的修改不再卡在特定的人或特定的電腦上。

不用找人

前端是最清楚需要什麼指令的人，現在可以自己改、自己發佈。

不綁電腦

建置交給 CI，任何有推送權限的電腦都能發佈。

不會對不上

三端用同一個版本號、同一份規格產生的程式碼，名稱不會打錯。

改壞會被擋下

工具會擋下重複名稱、過舊的版本，以及未確認的不相容修改。

第 7 章 · 各角色怎麼用

你只需要知道自己這一塊

前端

  • 第一次（專案還沒裝過）：
pnpm create @omniguider/bridge
  • 之後改 bridge/bridge.project.json，發佈：
pnpm bridge:publish
  • 只想升版或切換版本：
pnpm bridge
  • 需連上公司內網／VPN。

App（iOS／Android）

  • 不用安裝工具，也不改規格。
  • 收到前端通知後升版本號：
  • iOS：SPM 指定 tag nmmba-v0.2.0
  • Android：com.omniguider:nmmba-bridge-contract:0.2.0
  • 實作新指令要做的事。

請不要這樣做

  1. 不要手改 *.generated.* 檔案，下次產生會被蓋掉。
  2. 不要自己打 "nmmba.ui.xxx" 字串，用產生的常數。
  3. 不要手動建立或刪除版本標籤，推標籤就等於發佈。
  4. Pipeline 失敗時重跑它，不要改回手動上傳。
